# Requirements traceability

Use this method to show how a piece of work answers its requirements.

## Method

1. **List the requirements** with their identifiers, exactly as the source states them. Cite
   the evidence record for each. Do not merge, reword or add requirements.
2. **Trace forward.** For each requirement, find where the work addresses it and record how.
3. **Give each a status**: met, partly met, not met, or not addressed. Use *met* only when the
   work shows how; a statement of intent is *partly met*.
4. **Trace backward.** For each significant element of the work, find the requirement it
   serves. Record elements that serve none; they are scope without a reason.
5. **Report the gaps first**: requirements not addressed, then not met, then partly met.

## Rules

- A requirement missing from the trace is a defect in the trace, not a requirement that is met.
- Conflicts between requirements are reported, not resolved silently.
